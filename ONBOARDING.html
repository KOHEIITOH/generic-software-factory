初回オンボーディング

初回だけ実行設定と認証を用意します。設定済みならユーザーガイドの通常操作へ進めます。

1. 必要なもの

  • Git、uv、Python環境
  • Webビルド用のNode.js/npm
  • 開発実行用のDocker（CPU・メモリ等の制限を強制できること）と設定に指定した固定イメージ
  • 対象GitHub Repositoryと必要なIssue/PR書込権限
  • 利用するAIの認証。BedrockはPCの標準AWS認証、リージョン・モデルIDを設定

閲覧・設定診断にはAIの有料推論は不要です。開発実行時は要件・許可されたコードをAIへ送信します。

2. 依存関係と実行設定

uv sync --extra web --extra bedrock

GitHub/AIの認証、Dockerと依存入りの固定イメージをPCで準備します。認証情報はWebや設定ファイルに埋め込みません。

3. Webから初回登録

uv run sf web --rebuild

ターミナルの操作リンクを開き、「初回設定・Harness生成と改善」でRepositoryの絶対パスを指定します。GitHub名はoriginから検出します。変更範囲・検証・イメージ・Harnessの案を確認して承認すると登録できます。設定JSONの手作業は不要です。

既存Harnessがあれば再利用し、なければ最小ルールを生成します。Python unittest/pytestの静的検出ができれば検証案を用意します。依存の不足や未知のテスト方式は詳細欄で設定します。検証を省略して成功扱いにはしません。

この操作ではAI推論・Docker実行・GitHubへの変更・Repositoryへの書き込みは行いません。操作リンクは権限を含むため共有しないでください。

CLIから設定を登録する場合

従来の設定ファイルによる方法も利用できます。保存先と設定のdata_rootを一致させます。

uv run sf operator register --config /absolute/path/operator.json --name 開発対象

4. Issueを選択して実行

「開発を進める」でIssueを選び、実行範囲と料金説明を確認して「同意して実行・Draft PR作成」を押します。テストと独立レビューを通過するとPRリンクを表示します。取り込み・手動紐付け・デモPR作成はありません。

Harnessの改善

品質失敗の証拠があるWeb実行から、定型ルールの改善案を自動作成します。保存済み案で根拠と内容を確認し承認すると、新しい設定で再検証できます。自動適用・追加のAI推論・無限再試行は行いません。認証・通信・Dockerの失敗は改善効果の根拠にしません。

困ったとき

  • 操作権限がない: 起動したターミナルの操作リンクを開き直します。
  • 設定が無効: ローカルで変更内容を確認し、実行設定を再登録します。
  • Docker・認証の不足: 詳細操作の診断で確認します。開始前の不足は修正後、同じ有限予算内で再開できます。
  • 古いTask形式の保存先: 証跡を保管し、新しい保存先を指定します。自動変換・削除は行いません。

loopback上の単一利用者向けです。AWSリソース作成・デプロイ・PRの自動マージは行いません。Bedrock＋GitHubの実サービス通し確認は利用PCで実施してください。
