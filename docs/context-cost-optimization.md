# コンテキスト・トークン・コスト最適化設計（提案）

## 目的

Software Factoryの実行品質を落とさず、入力・推論・出力・再試行を含む**タスク全体の費用**を最適化する。特定のモデルやAI Runtimeに依存しない。

## 責務

- **Context Builder（Core）**: タスク・関連ファイル・差分・既存の設計決定から必要な情報を選択。除外理由と出典を記録する。
- **Context Budget（Core）**: 最大入力サイズ、必須情報、切り詰め優先順位を管理。モデルのコンテキスト上限を超えない。
- **Model Router（Core/Policy）**: タスクの難易度・必要能力・利用可能なモデル・コスト上限から選択。ルーティング先はAdapterとして交換可能。
- **Usage Tracker（Core）**: 入力・出力・推論（APIが提供する場合）・キャッシュ・再試行・推定/実測コストを記録。値が取得できない場合はunknownとし、ゼロとみなさない。
- **Provider/Runtime Adapter**: 利用可能なトークン数・料金メタデータ・推論設定などを共通形式に正規化。未対応機能を偽装しない。

## コンテキスト選択の順序

1. Taskの目的、制約、受け入れ条件、適用するハーネス・安全ポリシーは必須。
2. 変更対象のファイル名、構造、依存関係、差分を優先して探索する。
3. ファイル本文は必要な範囲を段階的に取得する。機密情報・無関係な大容量ファイルは送信しない。
4. トークン予算に収まらない場合は、情報を無言で欠落させず、再取得・タスク分割・承認を選択する。
5. 生成結果はテスト・レビューで検証する。要約やキャッシュは有効期限・入力ハッシュを付ける。

## コストと品質のガードレール

- タスク単位の入力/出力上限と推定費用上限を設定可能にする。
- モデルごとの課金方式は異なるため、価格表は外部設定として管理し、未登録料金はunknown扱い。
- キャッシュヒット、再試行回数、失敗率、品質ゲートの結果を同時に計測する。
- 料金最適化が安全・正確性・ユーザーの承認条件を上書きしない。
- 機密データの送信先、保存期間、プロバイダー別の保持条件を設定可能にする。
- プロンプトにリポジトリの指示文を無条件で信頼せず、信頼境界を明示する。

## 段階的実装

1. **Usage計測の共通スキーマ**: 推論APIのトークン情報とCLI Runtimeの計測可能範囲を整理する。
2. **Context Builder MVP**: 関連ファイルの絞り込み、予算、除外ログを実装する。
3. **Custom Agent MVP**: ModelProviderと安全な読み取りツールを接続し、明示的な許可の下で動作検証する。
4. **Routerとコスト制御**: モデル選択、料金設定、上限停止、再試行・キャッシュ戦略を追加する。
