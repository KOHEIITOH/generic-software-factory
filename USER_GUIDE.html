Software Factory 利用ガイド

GitHub Issueを選び、AI実装・隔離テスト・独立レビューからDraft PR作成まで進めます。

通常の操作

  1. 起動したターミナルの操作リンクからダッシュボードを開きます。
  2. 実行するIssueを選択します。複数の実行設定がある場合は先にRepositoryを選びます。
  3. 表示された変更範囲・検証内容・AIへの送信範囲・料金説明を確認し、「同意して実行・Draft PR作成」を押します。
  4. 進捗を確認し、完了したら「Draft PRを開く」から変更をレビューします。

手動のIssue取り込み・Repository紐付け・Project登録・デモPR作成は不要です。Bedrock利用時は推論料金が発生します。

実行中・失敗したとき

実行中は停止を要求できます。進行中の処理は完了する場合がありますが、次の操作境界で停止します。テスト・独立レビューに失敗した変更はPRにしません。

送信結果が不明な場合は「同じ送信を確認」を使います。同じIssueの再実行は保存済みRunを照合し、成功済みPRを重複作成しません。推論結果が不明な処理は自動再送しません。準備不足を修正して再開する場合も、試行回数・期限・予算は維持します。

必要なときだけ使う詳細操作

  • 診断: Docker・設定・GitHub接続などの開始条件を確認します。診断成功だけではAI認証や実通し成功を証明しません。
  • 要件分割: 登録設定の親Issueを分割し、計画を確認・承認してから子Issueを作成します。依存PRのマージ待ちで終了します。
  • レビュー対応: Factory製PRのRunを指定して同じPRへ有限回の修正を行います。
  • Project管理: 複数Repositoryのメタデータ管理です。開いたときだけ読み込みます。実行対象とHarnessは実行設定から適用します。

初回設定と現在の範囲

初回オンボーディングで依存関係・Docker・GitHub/AI認証・実行設定を用意してください。設定後の通常起動は次のコマンドです。

uv run sf web --rebuild

ローカルPCの単一利用者向けです。重要な変更・PRのマージ・リリースは人間が確認します。専用DBは必須ではありません。Bedrock＋GitHubの実サービス通し確認は利用者PCで行います。
